# 用 RecallGraph 查知识库

你面对的是**论文与个人笔记的图谱**，工具返回的是证据，不是结论。
你的任务是：找证据 → 核对原文 → 带引用回答。不要凭记忆补事实。

## 什么时候用

- 用户问某篇论文/某个方法的具体说法、数字、结论；
- 用户问自己以前的判断（"我是不是说过……""我之前怎么想的"）；
- 用户要求对比两篇材料、或区分"论文结论"和"我的推测"。

纯常识、与库里内容无关的问题，不要用。

## 调用顺序（不是硬流程，按需跳步）

1. **`search_materials(query)`** — 第一级检索。返回 claim_id / chunk_id / 文档标题 / 页码 / 原文引文，
   以及 `coverage`、`warnings`、`conflicts`。
   - 断言是**索引**：它可能丢了条件、抽错了主语、漏了反驳。涉及"为什么""怎么定义""具体数字"时不要停在断言。
   - 如果 `conflicts` 非空，说明不同来源对同一实体同一谓词有不同说法——逐条核对，别挑一个顺手的用。

2. **`read_evidence(chunk_ids=[...])`** — 第二级精读。拿第 1 步的 chunk_id 读原文，
   核对引文、补全条件和上下文。通常读 1–3 段就够。

3. **`query_knowledge_graph(entity, hops=1)`** — 需要看两个概念怎么连起来、或从线索往外扩时用。
   它返回关系与关联断言，适合探索，不适合核对精确事实。

4. **`recall_memories(query=...)`** — 用户提到自己过去的偏好、决定、被纠正过的说法时先调它。
   返回的记忆带 `valid_from`（何时为真）和 `recorded_at`（何时知道），能看出"当时怎么想、后来改没改"。

5. **`create_or_update_note(title, body, claim_ids=[...])`** — 你形成推论、总结或待办时写笔记。
   笔记不是论文结论，正文里要写清"这是推论"。

## 三条硬规矩

1. **每个事实性结论都要给来源**：文档标题 + 页码。没有证据就明说"库里没有"。
2. **记忆和证据冲突时以证据为准**，并明确告诉用户冲突在哪（哪条记忆、哪篇论文第几页）。
   不要为了顺着用户而修改事实。
3. **不要编页码**：页码只能来自工具返回值。`read_evidence` 返回的 `page_start`/`page_end` 才是准的。

## 输出格式

先给结论，再给证据：

```
结论：……

依据：
- 《论文标题》第 3 页：原文关键句（claim_id: ...）
- 你的笔记（2026-10-20）：……（与上面一致 / 与上面冲突）
```

如果证据不足，直接说：

```
库里只找到部分相关材料（见上），不足以回答"……"。缺的是：……
```

## 同一主 Agent 的在线调研能力

宿主还拥有 research-tools。用户同时要求近期外部资料时，按需阅读 research-briefing Skill，
用它搜索网页并管理对应 run_id。两套服务独立；不要启动 recallgraph.agent 循环。
本库文档的 chunk_id、页码与 research-tools 的 source_id 不可混用。
记忆提案不是提交，笔记不是论文事实；不要声称不存在的自动确认或同步已经完成。
